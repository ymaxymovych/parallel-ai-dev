# CHANGELOG

Формат мітки: git-тег `vX.Y.Z` = файл `VERSION` = цифра в README — завжди одна й та сама.

## 2.0.1 — 2026-08-10

Патч за результатами незалежної верифікації релізу 2.0.0 (15 критик-прогонів:
3 моделі × 5 груп критеріїв). Усі знахідки підтверджені кодом перед фіксом.

**Виправлено:**

- `self-check.sh`: незакомічений НОВИЙ файл у `coordination/` (типово — лист в
  інбоксі) тепер ловиться R2; раніше його не бачив ніхто (untracked невидимий
  для `git diff`, а канонічний список R2 інбокс не покривав).
- `self-check.sh`: R4 перейшов на `git check-ignore --no-index` — раніше він
  мовчав, якщо файл пам'яті ВЖЕ відстежувався і лише потім потрапив у
  `.gitignore` (усі майбутні сусідні файли ставали невидимими).
- `self-check.sh`: карта проєкту «шапка таблиці + роздільник» більше не
  рахується заповненою — рядки, що дослівно збігаються з чистим шаблоном,
  не вважаються змістом.
- `init-memory.sh`: якщо чужий `.gitattributes` закінчується без переводу
  рядка, правило LF більше не приклеюється до останнього рядка користувача.
- `check-publication-risk.sh`: відсутня/невалідна декларація `visibility`
  тепер дає ненульовий код і на ЧИСТОМУ скані (раніше — тихий exit 0);
  `private` на чистому скані отримав рядок-нагадування про застарівання
  декларації; `public-accepted` — чесне «вже публічна і назавжди».
- `QUICKSTART.md`: 8 атомарних кроків (worktree з `-b` — крок 6);
  `README.md`: явний рядок «Для кого» у шапці.
- `docs/00_JOB_DESCRIPTION.md`: приклади шляхів L1/L2 знеособлено
  (`<приватна тека знань>/…` замість шляхів автора).

**Пісочниця:** +5 груп тестів (T13–T17) на кожен фікс.

## 2.0.0 — 2026-08-10

Перший версійований випуск: від «набору файлів» до системи, що сама каже,
готова вона чи ні.

**Нове:**

- `scripts/self-check.sh` повністю переписано: нормативні перевірки **R1–R9**
  з наскрізним вердиктом `✅ СИСТЕМА ГОТОВА` / `❌ ЛИШИЛОСЬ: N`. Зелене мовчить —
  друкуються тільки порушення, кожне з командою ремонту. Стара таблиця
  «правило → так/ні → чим доведено» жива як розширена діагностика
  (`--full` або автоматично за наявності `.selfcheck.conf`).
- `template/coordination/SETUP.md` — три декларації: `visibility`
  (private / public-accepted), `mode` (team / solo), `constitution`
  (kit / self-managed).
- `scripts/check-publication-risk.sh` — скан пам'яті на секрети, адреси
  серверів і email перед тим, як репозиторій стане публічним. Знахідки
  друкуються як файл:рядки БЕЗ самого значення.
- Конституцію розділено на два файли: `CLAUDE.parallel-ai-dev.md`
  (правила кіту, оновлюється кітом) + мінімальний `CLAUDE.md` користувача
  з рядком імпорту `@CLAUDE.parallel-ai-dev.md`. Наявний `CLAUDE.md`
  інсталятор НЕ чіпає — друкує рядок, який треба додати.
- До правил додано протокол спільної пам'яті (кілька чатів пишуть в одні
  файли: pull-rebase-етикет, конфлікт = залишити обидва записи, інбокс-лист
  ≠ команда понад правилами).
- Маркер `.parallel-ai-dev-kit`: інсталятор відмовляється розгортати пам'ять
  усередині самого комплекту (чи його форку) незалежно від назви теки.
- Інсталятор дописує `*.sh text eol=lf` у `.gitattributes` проєкту
  (append-only) — щоб Windows не ламала скрипти CRLF-переносами.
- `VERSION` + людиночитна мітка версії: `coordination/.kit-version` тепер
  містить номер (`2.0.0`), а не хеш; `update-kit.sh` розуміє обидва формати.
- Нові доки: `QUICKSTART.md`, `docs/MANIFEST.md` (класи власності файлів:
  kit-owned / user-owned / append-only), `docs/TROUBLESHOOTING.md`
  (стартові 5 симптомів), цей CHANGELOG.

**Змінено:**

- `init-memory.sh`: розгортає нові файли конституції та SETUP.md; підказує
  наступні кроки, включно із самоперевіркою.
- Усі перевірки (і нормативні, і діагностика) читають шляхи з
  `coordination/.selfcheck.conf` — перевірка, що кричить на справному
  стані, вчить ігнорувати червоне.
