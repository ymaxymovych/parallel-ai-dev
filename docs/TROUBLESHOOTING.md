# TROUBLESHOOTING — симптом → причина → ремонт

> Стартова версія (2.0.0): п'ять найчастіших зупинок новачка. Повна добірка
> з реальних питань студентів — у версії 2.1.

| # | Симптом | Причина | Ремонт |
| --- | --- | --- | --- |
| 1 | `init-memory.sh: команду не знайдено` або купа помилок синтаксису одразу | скрипт запущено в PowerShell/CMD, а він для bash | відкрий **Git Bash** (ставиться разом із git) і запусти звідти: `bash ~/parallel-ai-dev/scripts/init-memory.sh` |
| 2 | `bad interpreter` чи `\r: command not found` | файл скрипта переконвертовано у CRLF (Windows-переноси рядків) | у теці комплекту: `git -C ~/parallel-ai-dev checkout -- scripts/` поверне оригінал; у своєму проєкті кіт сам дописує `*.sh text eol=lf` у `.gitattributes`, щоб це не повторювалось |
| 3 | `git worktree add` → `'<гілка>' is already checked out at …` | ця гілка вже відкрита в іншому дереві — одна гілка живе лише в одному дереві | створи дерево з НОВОЮ гілкою: `git worktree add ../проєкт-chat2 -b chat2`; список наявних дерев: `git worktree list` |
| 4 | конфлікт мерджу в `DECISIONS.md` / `WORKSTREAMS.md` | два чати дописали в один файл пам'яті — це нормальна робота, а не аварія | залиш ОБИДВІ версії записів (це журнал, записи не взаємовиключні), прибери лише маркери `<<<<<<<`/`=======`/`>>>>>>>`, закоміть |
| 5 | назбиралися покинуті робочі дерева | завершені чати не прибирали за собою | подивись список: `git worktree list`; прибирати ТІЛЬКИ `git worktree remove <шлях>` — НІКОЛИ не видаляй теку дерева як звичайну папку (правило 7 конституції: усередині можуть бути посилання на спільні залежності, і рекурсивне видалення вигребе код головного проєкту). ⚠️ `git worktree prune` лише чистить записи про вже зниклі теки — але це теж команда, що ЗМІНЮЄ стан: спершу подивись список |

Не знайшов свого симптому — подивись `docs/01_STARTER_KIT.md`, розділ
«Як усе зламати» (таблиця відомих способів вистрелити собі в ногу).
